# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A Worthy LMS — a single-page React 19 + Vite app for a Singapore tuition centre, deployed to Vercel at `lms.a-worthy.com` and wrapped via Capacitor for iOS/Android. Subjects: O-Level English (`eng`), O-Level Mathematics (`omath`), O-Level Additional Mathematics (`amath`), H1 General Paper (`gp`), H1 Economics (`h1econ`), H2 Economics (`h2econ`), IB MYP Mathematics (`ibmyp`).

`LMS.jsx` is ~600 lines (auth + shell + routing switch only); page components across `src/pages/`, all lazy-loaded. Pages, components, state, and data live in their own folders.

## Commands

```bash
npm run dev           # Vite dev server (localhost:5173)
npm run build         # Production build → dist/
npm run preview       # Preview the built dist/
npm run lint          # ESLint on **/*.{js,jsx}

# Capacitor (mobile wrapper — loads https://lms.a-worthy.com in a WebView)
npm run build:mobile  # vite build + npx cap sync
npm run cap:android   # build, sync, open Android Studio
npm run cap:ios       # build, sync, open Xcode

# Resource upload (one-off): re-uploads referenced files to Firebase Storage
# and rewrites fileUrl values in src — only used when adding new PDFs/DOCX.
node scripts/upload-resources.mjs
```

Deployment is via Vercel Git integration — pushing to `main` triggers automatic production deploy. `vercel.json` rewrites everything except `/api/*` and `/assets/*` to `index.html` (SPA). Domain: `lms.a-worthy.com`.

There is no test suite.

## Architecture

### Entry / shell
- `src/main.jsx` — React root, wraps `<App />` with `<BrowserRouter>`.
- `src/App.jsx` — wraps `<LMS />` in a `RootErrorBoundary` (catches top-level render failures with a safe fallback); `<LMS />` is the default export of `src/LMS.jsx`, named `LMSAuthWrapper`.
- `src/LMS.jsx` (~600 lines) — auth gate (Firebase `onAuthStateChanged`), then the main `LMS` component: sidebar, header, mobile bottom nav, global Cmd-K search, notification bell, toast container, offline indicator, and the `renderPage()` switch (wrapped in `<PageErrorBoundary>` + `<Suspense>`) that maps `state.page` → a lazy-loaded page component. Notifications and search results are memoized with `useMemo` with `Array.isArray` guards on all state arrays (Firebase can return indexed objects before sync normalises them). Global search indexes `resources`, `homework`, `posts`, and NAV labels only — do NOT index removed-feature state (a search result whose `page` has no `renderPage()` case / `PAGE_TO_PATH` entry will bounce the user to `/`). Mobile bottom nav uses `Confetti` icon for the Events tab. **Sidebar** is Bear-minimal: 232px open / 56px collapsed, `T.bgSidebar` (`#F2EFE8`) background, active items get a white card pill with a 2px rust accent left border, no dark panel. **Soft role gating** — the sidebar `NAV.filter` hides any group flagged `tutorOnly: true` (currently the **Manage** group: AI Marker, Attendance, Progress, Parent View) from non-tutors, and the global Cmd-K search drops the same items for students (`state.role !== "tutor"`). It is a *soft* gate: routes still render if reached directly (no hard block), so an old bookmark won't 404. The sidebar also filters subject groups by `enrolledSubjects` (matched from `state.students` by the logged-in email; `null` for tutors → all subjects shown). Shell elements carry IDs for print targeting: `id="lms-sidebar"` (aside), `id="lms-topbar"` (sticky header div), `id="lms-bottom-nav"` (mobile nav).
- **Login welcome animation** (`LMS.jsx`) — when the app shell mounts, a brief full-screen welcome overlay plays (warm-charcoal `#1C1B19` background + rust radial glow, A Worthy logo, the user's avatar/initials, and a time-of-day greeting "Good morning/afternoon/evening, {firstName}"). Built with framer-motion (staggered entrance), auto-dismisses after **1.4s** or on tap/click, and respects `prefers-reduced-motion` via the surrounding `<MotionConfig reducedMotion="user">` (transforms collapse to a fade). State is a simple `showWelcome` boolean in the `LMS` component.
- **First-login student onboarding overlay** (`LMS.jsx`) — a 3-step modal shown once to new students after Firebase confirms `state.role === "student"`. Gated by `aworthy-onboarding-done` localStorage flag. Steps: (1) Welcome + enrolled-subject badges, (2) Learning toolkit overview (Homework, Library, Community), (3) "You're all set" CTA → Dashboard. Triggered via `useEffect` on `state.role`; controlled by `showOnboarding` and `onboardingStep` state. Only shown when `!showWelcome && !showAvatarPrompt`. `dismissOnboarding()` sets the localStorage flag and resets state. Do not show to tutors.
- **Community announcements in bell** (`LMS.jsx`) — posts with `isAnnouncement: true` are surfaced separately from homework notifications. `unreadAnnouncements` is a `useMemo` derived from `state.posts` minus IDs stored in `localStorage` key `aworthy-read-announcements` (a per-user Set, so dismissing on one device does not affect others). Unread announcements appear at the top of the notification dropdown (amber `#FEF3C710` background, Megaphone icon, inline ✕ dismiss) and as an amber banner (`#78350F → #92400E`) below the topbar. The bell badge count is `notifications.length + unreadAnnouncements.length + returnedGrades.length`.
- **Notifications are role-aware** (`LMS.jsx`) — the `notifications` useMemo shows upcoming homework deadlines to everyone but the "N submissions pending grading" item to tutors only (`isTutor = state.role === "tutor"`). **Returned-grade notifications (the student feedback loop):** `returnedGrades` is a `useMemo` of the logged-in student's graded submissions (`myStudentId` matched from `state.students` by `authUser.email`) that haven't been acknowledged. Acknowledged IDs live in `localStorage` key `aworthy-seen-grades` (per-user Set, `dismissGrade(id)`). Returned grades appear as green rows at the top of the bell dropdown (with grade + inline ✕), and the most recent shows as a green banner (`#14532D → #166534`) below the topbar with a "View feedback" button (→ homework). A one-time system `Notification` fires per newly-returned grade, tracked separately in `aworthy-notified-grades` so it never re-fires across sessions. A one-time backfill (guarded by `aworthy-grades-initialised`) marks all grades that exist when the feature first loads as seen, so existing students are not flooded with historical grades. **Permission is requested on first bell open** (a user gesture) rather than at mount — browsers increasingly require a gesture before showing the prompt.
- **Live Classroom** (`src/pages/Classroom.jsx`) — 44-line component that auto-opens `https://whiteboard.a-worthy.com` in a new tab on mount, with a fallback launch card if the popup is blocked. The built-in canvas whiteboard has been fully removed.
- **Dashboard** (`src/pages/Dashboard.jsx`) — the root `Dashboard` export is **role-aware**: `state.role === "tutor"` → `TutorDashboard`, otherwise `StudentDashboard`. (Both are real, rendered components — do not revert `Dashboard` to always returning `TutorDashboard`.) TutorDashboard layout: `TutorGreeting` (time-aware "Good morning/afternoon/evening" + "Welcome to the A-Worthy World, {firstName}." heading + contextual subline showing pending submission count or all-clear) → `QuickActionPills` (4 pill buttons: Grade Homework with pending badge, Take Attendance, View Progress, Community) → stat tiles (Resources, To Grade, Students, Sessions, Community — "To Grade" tile highlights in `T.accent` colours when `pendingSubmissions > 0`) → 2-column grid: left (subject cards with real resource counts + `UpcomingSessionsCard` showing next 3 sessions with subject-themed calendar tiles) / right (Community posts preview + Quick Actions list). No HeroBanner, no duplicate pending-submissions banner. All cards draw from real `state` data. **StudentDashboard** layout: `Greeting` → `FocusCard` ("Start here") → 2-column grid. **`FocusCard`** is the calm front door: it shows up to **3 prioritised next steps** — (1) resume/start the most pressing homework (in-progress → overdue → not-started), (2) mistakes due for spaced-repetition review, (3) the nearest exam countdown — then fills any remaining slots with friendly starters (Explore your subjects → `subjects`, Build vocabulary → `vocab`, Community), so brand-new students with no data still get a guided, non-empty landing. It replaced the old `ResumeCard` hero. Right column: `WeekProgressCard` → `RecentSessionsCard` (last 3 sessions that have tutor notes, hidden when none exist) → `BookmarksCard` (up to 4 bookmarked resources with inline `DocumentViewer`) → `ExamCountdownCard` (reads `state.customExams`, shows "Custom" badge for non-standard entries) → `GradeHistoryCard` (last 6 graded submissions as a colour-coded strip + subject breakdown chips; hidden when no graded submissions) → `RecentlyReturnedCard` → `WordOfTheDayCard`.
- **My Subjects hub** (`src/pages/Subjects.jsx`) — route `subjects` / `/subjects`, nav item "My Subjects" in the Overview group (icon `Compass`). A calm visual launchpad: a card grid of the student's enrolled subjects (filtered by the `enrolledSubjects` prop from `LMS.jsx`; tutors see all). Each card shows a `SubjectIllustration` band (click → that subject's Resources), real resource + practice-paper counts, and quick-link chips that mirror the subject's actual sidebar nav items via the `SUBJECT_TOOLS` map (eng → Resources/Vocabulary/Practice Papers; gp → Example Finder/Model Essays/Practice Papers; all others → Resources/Practice Papers). It consolidates the per-subject Resources/Practice-Papers entry points into one inviting page without removing the deep-linkable per-subject routes.

### Code splitting
- All page components are loaded via `lazy()` from React — each page becomes its own chunk at build time.
- `renderPage()` is wrapped in `<Suspense fallback={...}>` for loading states.
- Role gating is **navigation-only (soft)**: `renderPage()` still has a `case` for every route and any authenticated user who reaches a URL directly will get the page. The only gate is in the sidebar/search (`tutorOnly` groups hidden from students) — there is no hard route block.

### State management
- One `useReducer` in `LMS.jsx`: `appReducer` (in `src/state/reducer.js`) with ~47 action types. State shape and initial values are in `src/state/persistence.js` (`DEFAULT_STATE`).
- `initialState` is rehydrated from `localStorage` key `aworthy-lms-state` on load. Only keys listed in `PERSIST_KEYS` are persisted: `bookmarks`, `attendance`, `submissions`, `homework`, `pastPaperDocs`, `studyLogs`, `announcement`, `mistakes`, `revisionChecklist`, `posts`, `reports`, `myAvatar`, `studentAvatars`, `students`, `resourceMeta`, `sessions`, `customExams`, `collections`, `homeworkTemplates`, `resources`, `events`. Everything else re-seeds from `src/data/seedData.js` on every load. (`ratings`, `notes`, `goals`, and `videoLessons` have all been removed from both `DEFAULT_STATE` and `PERSIST_KEYS` — their features were deleted, so the state, the reducer cases that mutated them, and their seed data are all gone. Do not reintroduce them.) **`resources` is now persisted** — user-uploaded resources survive page refresh. `loadPersistedState()` merges any missing seeded resource IDs back in (same pattern as `pastPaperDocs`) so seeded resources always appear even after users upload their own.
- **`customExams`** — `state.customExams` (`[]`, persisted) holds tutor-created exam entries supplementing the hardcoded Singapore exam schedule. Shape: `{ id, name, date, subject, paper }`. Actions: `ADD_CUSTOM_EXAM` (payload: `{ name, date, subject, paper }`) and `DELETE_CUSTOM_EXAM` (payload: id). Managed via the collapsible "Manage Exam Dates" panel in `ProgressTracker.jsx`. All exam countdown views (`getExamCountdowns`, Dashboard, ParentView, PublicReport) accept and merge these custom entries, marking them with `isCustom: true`.
- **`resourceMeta`** — `state.resourceMeta` (`{}`, persisted) stores per-resource metadata that shouldn't live on the `resources` array itself (which always reloads from seedData). Currently holds `{ difficulty: "easy" | "medium" | "hard" }` per resource ID. Updated via `SET_RESOURCE_DIFFICULTY` action: `{ id, difficulty }`. Access as `state.resourceMeta?.[resource.id]?.difficulty`.
- **`events`** — `state.events` (`[]`, persisted) holds all LMS events (competitions, challenges, etc.). Seeded from `initialEvents` in `src/data/seedEvents.js`; `loadPersistedState()` merges any missing seeded event IDs without overwriting user-created ones. Shape: `{ id, title, emoji, color, startDate, endDate, status: "upcoming"|"active", description, howToParticipate, participants: [], prizes: [], criteria: [] }`. Actions: `ADD_EVENT` (payload: form fields; auto-assigns `id`, seeds empty `participants`/`prizes`/`criteria`) and `DELETE_EVENT` (payload: id). **Role-gated:** only tutors see the "+ Create Event" button and delete controls; both use `window.confirm()` for destructive operations.
- **`TOGGLE_COLLECTION_RESOURCE`** — action (payload: `{ collectionId, resourceId }`) that toggles a resource ID in/out of `collection.resourceIds`. Used by the "Save to collection" picker on `ResourceCard`.
- **`role` is NOT persisted** — it always comes from Firebase RTDB on login (via `SET_ROLE`). `state.role` drives **soft role gating**: it hides `tutorOnly` NAV groups from the sidebar + search and flips the in-page `isTutor` flag in `ContentLibrary.jsx` / `PastPapers.jsx` (`state.role === "tutor"`) so students don't see upload / delete / difficulty-setter controls. It does not hard-block any route.
- Adding a new persistent field requires adding it to both `DEFAULT_STATE` and `PERSIST_KEYS`.
- localStorage writes are debounced (300ms). Firebase sync (`src/hooks/useFirebaseSync.js`) is also debounced (2s) and uses a write guard to prevent read-write loops.
- `MERGE_FIREBASE_STATE` handles two cases: (1) if the current state key is an array and Firebase returned a plain indexed object (`{"0":…,"1":…}`), it reconstructs the proper JS array so callers can safely use `.find`/`.filter`; (2) if both the current state and Firebase value are plain objects (e.g. `attendance`), it does a **recursive deep-merge** (`deepMerge` helper in `reducer.js`) so nested objects like `{sessionId: {studentId: status}}` are merged level-by-level rather than overwritten. Arrays nested inside synced objects (e.g. `post.comments`) are not normalised by MERGE — guard them at the point of use with `Array.isArray`.
- Pages receive `{ state, dispatch }` as props. There is no Context or external store.

### Routing (URL ↔ state.page two-way sync)
- `src/data/routing.js` is the source of truth for both sidebar nav (`NAV`) and the URL map (`PAGE_TO_PATH` / `PATH_TO_PAGE`).
- `LMS.jsx` has two effects: one reads `location.pathname` and dispatches `SET_PAGE`; the other watches `state.page` and calls `navigate(path)`. An `initializedRef` prevents the first render from racing.
- `renderPage()` in `LMS.jsx` is a `switch` on `state.page` returning the page component. Adding a page = (1) component file, (2) entry in `NAV`, (3) entry in `PAGE_TO_PATH`, (4) `case` in `renderPage()`, (5) lazy import at top of `LMS.jsx`.
- Subject-scoped page IDs use consistent suffixes: `library-eng`, `pastpapers-gp`, `library-h1econ`, etc. Shared library and past-papers pages have subject-suffixed NAV IDs that **each map to a unique route path**. **Critical invariant:** every page ID must have a unique path in `PAGE_TO_PATH`, because `PATH_TO_PAGE` is the auto-generated reverse map — if two IDs share one path, the round-trip collapses them to a single ID and the URL↔state sync bounces the user to `/`. (This is exactly what broke the subject Resources tabs: all `library-*` IDs once shared `/library`.) The base `library` ID (used by mobile nav + search) maps to `/library`; each subject library maps to `/library/{subject}`.
- URL slugs use hyphens: `/subjects`, `/example-finder`, `/ai-marker`, `/ai-feedback`, `/calendar`, `/past-papers/eng`, `/past-papers/gp`, `/past-papers/h1econ`, `/past-papers/h2econ`, `/past-papers/omath`, `/past-papers/amath`, `/past-papers/ibmyp`, `/library`, `/library/eng`, `/library/h1econ`, `/library/h2econ`, `/library/omath`, `/library/amath`, `/library/ibmyp`.
- **Public report route** (`/report/:token`) — handled by `LMSAuthWrapper` *before* the auth check: if `location.pathname.startsWith('/report/')`, the token is extracted and `<PublicReport token={token} />` is rendered directly, bypassing Firebase Auth entirely. `PublicReport` (`src/pages/PublicReport.jsx`) is a non-lazy import so parents can access it without the app shell loading. It reads from `publicReports/{token}` in Firebase RTDB (public read, see database rules) and shows a branded progress report with grade history, attendance, recent session notes, and exam countdowns. Expired (> 7 days) or missing tokens display a friendly error.
- **Removed routes** (do not re-add): `goals`, `timedwrite`, `notes`, `practice-gp`, `practice-h2econ`, `micro-gp`, `exams-h1econ`, `exams-h2econ`, all `micro-*` routes, `infographics`, `essaygrader`, and all subject-scoped `videos-*`, `practice-*`, `formulas-*` routes. The lazy imports for `VideoLessons`, `LiveInfographics`, `SubjectDrills`, `EssayGrader`, `NotesPage`, and `FormulaCards` have been fully removed from `LMS.jsx`, and their `renderPage()` cases are gone. Do not re-add them. Each subject nav group now only contains Resources (`library-*`) and Practice Papers (`pastpapers-*`); English also has Vocabulary; GP has Example Finder and Model Essays.
- **Current active subject nav items per subject:** `eng` → Resources, Vocabulary, Practice Papers; `omath`/`amath`/`h1econ`/`h2econ`/`ibmyp` → Resources, Practice Papers; `gp` → Example Finder, Model Essays, Practice Papers.
- **Non-subject NAV groups:** `Overview` (Dashboard, My Subjects, Live Classroom) → subject groups → `My Work` (Homework, **Schedule** (was Calendar), AI Feedback) → `Revision` (**Learning Progress** (was Revision Checklist), Collections) → `Community` (Community, Events) → `Manage` *(tutorOnly)* (AI Marker, Attendance, Progress, Parent View) → `System` (Settings). `Homework` lives in `My Work` (not `Manage`) so A-Worthlings keep access — `Homework.jsx` is role-split internally (`state.role === "tutor"` → `TutorHomework`, else `StudentHomework`). **Schedule** (`src/pages/Schedule.jsx`) is a tab shell: `calendar` page → Calendar tab, `revisiontimetable` page → Revision Timetable tab; accepts and passes `enrolledSubjects` to the timetable. **Learning Progress** (`src/pages/LearningProgress.jsx`) is a tab shell: `checklist` page → Topics tab, `mistakes` page → Mistake Journal tab; accepts and passes `enrolledSubjects` to the checklist. Both merged pages keep their original `PAGE_TO_PATH` entries so old bookmarks still navigate to the correct tab.
- **"Past Papers" → "Practice Papers" rename:** All sidebar nav labels for `pastpapers-*` items and the `PastPapers.jsx` page title/subtitle/upload heading use "Practice Papers". The URL slugs (`/past-papers/*`) are intentionally unchanged to preserve existing bookmarks — only the display label changed.

### Page / component layout
- `src/pages/*.jsx` — top-level pages mapped from the route switch.
- `src/pages/{homework,study,tools}/` — grouped feature folders.
  - `pages/tools/` contains both student tools (PomodoroTimer, VocabBuilder) and the tutor AI grading tool (AIMarker), plus the AI grading utilities (`extractText.js`, `gradeClient.js`, `rubrics.js`). `PracticeQuestions`, `SubjectDrills`, `EssayGrader`, `FormulaCards`, `TimedEssayWriter`, and `NotesPage` have been **deleted from the repository** — do not recreate them.
- `src/components/ui/` — 19 design-system primitives (`Btn`, `Card`, `Badge`, `Progress`, `Input`, `Select`, `Textarea`, `StatCard`, `EmptyState`, `DocumentViewer`, `PageHeader`, `PageErrorBoundary`, `BackBtn`, `BackToTop`, `FileIcon`, `InstallPrompt`, `LoadingSkeleton`, `SimpleQRDisplay`, `SubjectIllustration`). Prefer these over ad-hoc markup. `Card` supports keyboard accessibility when `onClick` is provided. `DocumentViewer` has a focus trap for accessibility. **PDF rendering:** PDFs are never embedded directly via `<iframe src={firebaseUrl}>` — Firebase Storage sets `X-Frame-Options: SAMEORIGIN` which Chrome blocks, and iOS Safari cannot render cross-origin PDFs inline. Instead, `DocumentViewer` routes PDFs through `https://docs.google.com/viewer?url=<encoded absolute URL>&embedded=true`, which fetches and renders the PDF server-side. Relative `fileUrl` values are resolved to absolute with `url.startsWith('http') ? url : window.location.origin + url` before encoding. On mobile (`useWindowWidth() < 768`), the iframe is replaced with an open/download card — native browser/OS PDF viewers handle pinch-zoom and scrolling better than iframes.
- `src/components/gamification/` — `StudentAvatar` component + avatar system. Exports: `AVATAR_ICONS` (16 icons: star, crown, lightning, brain, flame, trophy, sparkle, target, rocket, grad, heart, palette, atom, compass, leaf, music), `AVATAR_COLORS` (8 palettes: coral, amber, forest, teal, violet, rose, rust, slate), `decodeAvatar(key)` (splits `"{iconKey}-{colorKey}"` composite), `AvatarDisplay` (renders icon+colour given an avatarKey), `AvatarPicker` (inline 4×4 icon grid + colour swatches + Save/Cancel). Default `StudentAvatar` resolves key via `avatarKey ?? (avatarMap && student?.id != null ? avatarMap[student.id] : null)`, falls back to warm-gradient initials. Avatar state: `state.myAvatar` (logged-in user's key, persisted) and `state.studentAvatars` (map of studentId→key, persisted). Actions: `SET_MY_AVATAR` (payload: key), `UPDATE_STUDENT_AVATAR` (payload: `{ studentId, avatar }`). **Self-service sync:** when an A-Worthling saves their avatar (Settings page or first-login modal), `UPDATE_STUDENT_AVATAR` is also dispatched — matched by `authUser.email` against `state.students` — so the choice propagates to Community, Attendance, and ProgressTracker without tutor intervention. **First-login prompt:** `LMS.jsx` shows a one-time avatar-picker modal when `state.myAvatar === null`; gated by `aworthy-avatar-prompted` localStorage flag so it only appears once. Save dispatches both avatar actions; "Skip for now" or backdrop-click sets the flag without choosing. **Surfaces:** Sidebar (logged-in user), Settings (editable), ProgressTracker (tutor-editable per A-Worthling), TutorHomework submissions list, StudentHomework list-view header, ParentView report header, Community posts/comments, Attendance by-A-Worthling list.
- `src/components/toast/` — `ToastContainer` listens to `state.toasts`; dispatch `{ type: "ADD_TOAST", payload: { message, variant } }` (`variant`: `success` | `error` | `info`).

### Data / config
- **Content Library** (`src/pages/ContentLibrary.jsx`) — sidebar folder tree (subjects → topics with resource counts) + main panel. Root view shows subject cards; subject view shows only topics that have resources (empty topics hidden); topic/search/filter view shows a flat resource grid. Features: type filter pills (All/PDF/Video/DOCX), sort toggle (Newest/A–Z), bookmark toggle, difficulty tags (Easy/Medium/Hard), offline save, **"Save to collection" picker** (FolderSimpleStar button → inline dropdown of available collections; dispatches `TOGGLE_COLLECTION_RESOURCE`; shows a badge when a resource is in one or more collections), and delete button (`window.confirm()` before dispatching `DELETE_RESOURCE`). The `ResourceCard` inner component is shared across all grid views. **Role-gated controls:** `isTutor = state.role === "tutor"` — only tutors see Upload, the delete button, and the per-card Easy/Medium/Hard difficulty *setter*; students still see the read-only difficulty *badge*, bookmark, offline-save, collection-picker, and view. The collection picker only renders when `state.collections` is non-empty. The subject folder tree + all-subjects grid are filtered to the student's `enrolledSubjects` prop (passed from `LMS.jsx`; `null` for tutors → all subjects). **Upload panel** (`UploadPanel` component at top of file, tutors only): multi-file drag-and-drop zone + file browser (multiple files accepted); shared Subject selector and free-text Topic/Folder field (suggestions from `TOPICS[subject]` via `<datalist>`, but any custom text creates a new folder on upload); per-file editable title (auto-filled from filename via `titleFromFilename()`) and type selector; per-file progress bar using `uploadBytesResumable`; uploads to Firebase Storage at `resources/{subject}/{topic}/{timestamp}_{filename}` and dispatches `ADD_RESOURCE` with the resulting `fileUrl`. Topics are derived dynamically from actual resource data (`allTopics` useMemo), so a user-created topic folder appears in the sidebar as soon as the first file is uploaded into it — no separate "create folder" step.
- **Calendar** (`src/pages/Calendar.jsx`) — week/month toggle view of sessions, homework due dates, and exam dates. Route: `calendar` / `/calendar` (rendered inside `Schedule.jsx`). Week view: 7-column day grid with `SessionChip`, `HwChip`, and `ExamChip` (amber, from `getExamCountdowns(state.customExams)`). On mobile (`useWindowWidth() < 768`), week view switches to a vertical day-list layout. Month view: 6×7 grid with exam chips, today highlight, and overflow count. Navigation: prev/next/today buttons. Legend includes Session, Homework due, and Exam date. No state writes — read-only.
- **AI Essay Feedback** (`src/pages/tools/AIFeedback.jsx`) — student-facing self-serve grading. Route: `aifeedback` / `/ai-feedback`. Subject + topic selects auto-pick a rubric silently via `pickDefaultTask` + `rubricToText` (no rubric editor shown to students). Supports drag-and-drop file upload and paste textarea. Calls `gradeSubmission` from `gradeClient.js`. Results show grade header, strengths/improvements cards, criteria bars, and collapsible full report. No rubric editor is exposed — students cannot see or edit the marking criteria.
- `src/data/seedData.js` — all initial collections (resources, video lessons, exams, students, sessions, attendance, reports, posts, homework, submissions). Resource `fileUrl`s point to Firebase Storage download URLs. Also exports `initialPastPaperDocs` (3 seeded English practice papers — 1184 Specimen Paper 2, CHIJ KC 2025 Prelim, and Practice 1 Caregiving Challenges — formerly in `initialResources`, now seeded into `state.pastPaperDocs`).
- `src/data/{routing,subjects,gpQuestionTypes,infoPackThemes,microModules,practiceQuestions,essayData,vocabDrills,seedEvents}.js` — static content used by individual pages. `pastPapersData.js` exists but is no longer used — Practice Papers is now a dynamic document folder.
- **Practice Papers** (`src/pages/study/PastPapers.jsx`) — documents stored in `state.pastPaperDocs` (persisted), uploaded to Firebase Storage. Documents are grouped by **Year (descending) → School (ascending)**. Each document has `{ id, name, fileName, url, subject, fileType, year, school, uploadedAt, uploadedBy }`. **Upload panel** (`UploadPanel` component): multi-file drag-and-drop zone accepting PDF and DOCX; shared Year (dropdown) and School/Source (`<datalist>` with SG school suggestions, free-text to create new groups); per-file editable label (auto-filled from filename); per-file progress bar using `uploadBytesResumable`; uploads to `past-papers/{subject}/{year}/{school}/{timestamp}_{filename}`. Existing docs without `year`/`school` fields appear under "Uncategorised". Year and school groups are collapsible (open by default). **Seeded documents:** `DEFAULT_STATE.pastPaperDocs` is initialised from `initialPastPaperDocs` in `seedData.js`; `loadPersistedState()` merges any missing seeded IDs into the existing localStorage array so existing users receive new seeded papers without clearing state. **Inline DocViewer:** the modal `DocViewer` component inside `PastPapers.jsx` uses the same Google Docs Viewer approach as `DocumentViewer` — it resolves relative URLs to absolute (`url.startsWith('http') ? url : window.location.origin + url`) then passes them to `https://docs.google.com/viewer?url=<encoded>&embedded=true`. ### AI grading (Claude)
- **Server:** `api/grade.js` is a Vercel serverless function that calls the Anthropic Messages API (`https://api.anthropic.com/v1/messages`) with vision support. Body shape: `{ subject, topic, question, rubric, instructions, text, images: [{ mediaType, base64, label }] }`. Returns a structured `{ grade, overallPercent, summary, strengths[], improvements[], criteria[], report, model }`. Claude is prompted to emit a `<grade-json>…</grade-json>` header followed by a markdown report; the function tolerantly parses either tag-wrapped or bare JSON. Body size limit is set to 20mb on the route; default model is `claude-sonnet-4-6`.
- **Required env vars** in Vercel: `ANTHROPIC_API_KEY` (required). Optional: `ANTHROPIC_GRADING_MODEL` to override the default model. Without the key, the rest of the LMS still works; only the auto-grade buttons fail with a clear toast.
- **Client engine** lives in `src/pages/tools/`:
  - `rubrics.js` — pre-built rubrics keyed by `{subject}.{taskKey}` (e.g. `gp.essay`, `gp.saq`, `eng.comprehension`, `h2econ.essay`). `pickDefaultTask(subject, topic)` chooses the right task by inspecting the topic string; `rubricToText()` flattens a rubric to the human-readable text passed to Claude; `getDefaultRubricForHomework(subject, topic)` is the convenience wrapper used by the homework UI.
  - `extractText.js` — client-side submission extraction: `mammoth` for DOCX, `pdfjs-dist` for PDFs (renders first 8 pages to PNG via `canvas` if the PDF has no extractable text), and a canvas-based downscaler for photos (long edge 2048px, re-encoded as JPEG q0.85) so payloads stay under Vercel's request limit. `extractFromFile(File)` for local pickers; `extractFromUrl(url, name)` for Firebase Storage URLs already on a submission; `mergeExtractions([…])` combines several into one `{ text?, images?, warnings? }` payload.
  - `gradeClient.js` — thin POST wrapper around `/api/grade`.
- **Two surfaces consume the engine:**
  - **Homework auto-grade** — `TutorHomework.jsx` adds a rubric textarea to the create form (auto-fills via `getDefaultRubricForHomework` and is fully editable), a collapsible rubric editor on the detail view (dispatches `UPDATE_HOMEWORK_RUBRIC`), and an "Auto-grade" button (with `Sparkle` Phosphor icon) on each submitted item that fetches the student's files, extracts them, calls the grader, dispatches `SAVE_AI_GRADE`, and pre-fills the existing grading panel. The AI's draft is held in `submission.aiGrade` and never reaches `submission.grade` until the tutor hits "Save Grade" — tutor-in-the-loop by design.
  - **Standalone AI Marker** — `src/pages/tools/AIMarker.jsx` (route `aimarker` under the Manage nav) for ad-hoc submissions not tied to a homework. Drag-drop or pick files, optionally type a question, hit mark.
- **Reducer additions:** `ADD_HOMEWORK` now defaults a `rubric: ""` field and seeds `aiGrade: null` on each new submission. New actions: `SAVE_AI_GRADE`, `CLEAR_AI_GRADE`, `UPDATE_HOMEWORK_RUBRIC`. Persistence is unchanged — `homework` and `submissions` were already in `PERSIST_KEYS`, so the new sub-fields ride along automatically.
- **Sister repo:** `aworthysg/afk-mark-` is a standalone Vite + React app that ships the same `src/grading/` engine + `api/grade.js` function under a single-page UI. Use it as the reference when refactoring the engine — keep both copies in sync (no shared package yet).

### PWA / Capacitor
- `public/sw.js` (cache names `aworthy-lms-v15`, `aworthy-assets-v15`, `aworthy-resources-v1`) — cache-first for `/assets/*` (immutable hashed filenames), network-first with 4s timeout for navigation (falls back to cached `/index.html`), network-first with 5s timeout for everything else. **`aworthy-resources-v1`** is a dedicated cache for explicitly saved Firebase Storage documents: the SW listens for `CACHE_RESOURCE` messages (fetches the URL with `mode: 'cors'` and stores it) and `UNCACHE_RESOURCE` messages (deletes from cache). Firebase Storage fetch requests (`url.hostname.includes('firebasestorage.googleapis.com')`) are served cache-first from `aworthy-resources-v1` when a saved copy exists. **Bump both `aworthy-lms-*` and `aworthy-assets-*` cache names whenever you change shell assets or deploy significant JS changes** — this forces all cached devices to evict stale bundles. Do not bump `aworthy-resources-v1` (it holds user-saved files).
- **Print / Save PDF** — `index.html` contains `@media print` CSS that hides `#lms-sidebar`, `#lms-topbar`, `#lms-bottom-nav`, and `.no-print` elements; removes padding from `main`; and sets `@page { margin: 15mm }`. Apply `className="no-print"` to any element that should be hidden when printing (e.g. action buttons in ParentView).
- `public/manifest.json` + apple-touch icons in `index.html`. Background color matches `T.bg` (`#FAFAF7`).
- `index.html` root CSS uses `min-height: 100dvh` (not `height`) on `html`, `body`, and `#root` — iOS Chrome with its collapsing address bar dynamically changes the `dvh` unit, and a fixed `height` on body caused the root to collapse to zero-height before React mounted, producing a blank page.
- `capacitor.config.ts` points the native shell at the **live URL** (`https://lms.a-worthy.com`) rather than the bundled `dist/`. To ship a fully offline mobile app, remove the `server.url` and rebuild.
- The app shows toast notifications when going offline/online.
- **iOS Safari compatibility** — never use bare `Notification`, `PushManager`, or other Web APIs that Safari may not define as globals. Always guard with `typeof X !== "undefined"` or `"X" in window` before accessing them. Failing to do so throws a `ReferenceError` that propagates through React and crashes the entire app on iOS.

## Conventions

- **JavaScript + JSX only** (no TypeScript outside `capacitor.config.ts`). ESLint enforces `no-unused-vars` with an exception for identifiers starting with uppercase or underscore.
- **React 19 hooks only.** No class components.
- **No emojis in UI** — use Phosphor icon components from `src/icons/icons.jsx` for all indicators, buttons, and decorative elements.
- **Inline styles via `T`.** Don't introduce CSS modules, Tailwind, or styled-components — the codebase deliberately uses inline `style={{ ... }}` driven by tokens in `src/theme/theme.js`. Use `T.fontDisplay`, `T.fontBody`, `T.fontMono`, `T.fontSerif` for font families — never hardcode font-family strings. Global typography/animations are in the `<style>` block in `index.html` and the small `src/index.css`.
- **Never use old blue/purple palette** — the colours `#2D3A8C`, `#4F5BD5`, `#6366F1`, `#8B5CF6`, `#0F172A`, `#1E2A4A`, `#818CF8` have been fully purged. Accent is `T.accent` (`#C0392B` rust red). Dark hero banners use warm charcoal (`#1C1B19`→`#2A2927`) with a subtle rust glow, never dark navy.
- **Dark mode** is controlled via the Settings page toggle. It sets `html.dark` class; basic CSS overrides exist in `index.html` for body, scrollbar, glass-header, etc. The inline `T` tokens do not change for dark mode.
- **Accessibility** — icon-only buttons must have `aria-label` attributes. Modals must have `role="dialog"`, `aria-modal="true"`, and `aria-label`. Modals should implement focus traps (Tab/Shift+Tab cycling, Escape to close). Logo images need descriptive alt text. `Card` component has built-in keyboard support when clickable. Toggle switches should have `aria-describedby` linking to their description text. Minimum touch target is 44×44px for interactive elements.
- **British English in all UI copy** — this is a Singapore tuition centre. Use British spelling everywhere (`colour`, `recognised`, `organised`, `minimised`, `fulfilment`) and the British verb/noun split for *practise/practice*: **"practise" is the verb** ("time to practise", "Practise all"), **"practice" is the noun** ("practice session", "Comprehension Practice"). Keep new copy consistent.
- **Destructive actions** (archive homework, clear AI grade, delete resource, delete past paper) must use `window.confirm()` before dispatching.
- **PageHeader** — use the `PageHeader` component from `src/components/ui` for consistent page titles. It accepts `title`, `subtitle`, and `action` props.
- **Mobile-first responsive.** `src/hooks/useWindowWidth.js` is used to switch layouts; the breakpoint is `< 768px`. On mobile, sidebar becomes a slide-over and the bottom nav bar appears.
- **No gamification** — the XP/coins/streak/leaderboard/badges/wallet system and all mini-games have been fully removed. `state.wallet` does not exist. Do not re-introduce gamification imports, game routes, celebration overlays, or wallet state references.

Do not re-add quiz routes, `peerEssays`, or `peerReviews` state keys. `state.quizzes` does not exist and `student.quizResults` is always empty (legacy field) — always use `(state.quizzes || [])` null-guard if touching legacy student data. `PeerReview.jsx` has been deleted.
